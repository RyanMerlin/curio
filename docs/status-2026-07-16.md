# Curio Public Baseline Status

**Snapshot:** 2026-07-16
**Repository:** [RyanMerlin/curio](https://github.com/RyanMerlin/curio)
**Default branch:** `main`

This document is the handoff snapshot after Curio's first public release. It
separates shipped behavior from the adoption roadmap so maintainers and
contributors can resume work without reconstructing launch state from issues or
chat history.

## Published baseline

- GitHub release `v1.0.1` is public with Linux x86-64, macOS Apple Silicon, and
  Windows x86-64 archives plus `SHA256SUMS`.
- The credential-free demo and release installation path are documented in the
  README and launch material.
- The Rust package is named `curio-km`; the library and executable remain named
  `curio`.
- Crates.io publication is not complete because maintainer registry credentials
  are not configured in the release environment.
- Docker is not a verified launch path and must not be presented as one until
  the image export issue is resolved.

The release tag points to `5a2c6f4`. Post-release retrieval work is intentionally
on `main` and remains under the `Unreleased` changelog section.

## Shipped after v1.0.1

Commit `8a1fbf0` adds deterministic published-knowledge retrieval:

- `curio retrieve --query <text> --json`
- reads only `wiki/published/`
- deterministic lexical ranking and cited excerpts
- stable path-derived result IDs
- source URI, content hash, update time, authority, and optional Git provenance
- validation for empty and stopword-only queries

The focused retrieval suite contains seven tests. At this snapshot, the full
Rust suite contains 94 passing tests and the current `main` CI and release matrix
are green.

## GitHub baseline

- `main` prevents deletion, force pushes, and non-linear history.
- Seven checks are required: format, clippy, nextest, release build, and the
  Linux, macOS, and Windows build/package jobs.
- Required matrix contexts were repaired on 2026-07-16 after release archive
  names changed; they now exactly match the active workflow job names.
- No open Dependabot security alerts were reported by the repository API.
- Code scanning is not configured. Secret-scanning alert enumeration requires
  an additional GitHub token scope and was not independently verified.
- The repository has no open product bugs at this snapshot.

## Recommended next sequence

1. Finish the `fetch` contract for IDs already emitted by `retrieve`.
2. Add the deterministic evaluation corpus and publish baseline metrics.
3. Wrap shared search/fetch code in a local read-only stdio MCP server.
4. Refactor existing source intake behind an adapter contract, then add a
   GitHub/local Markdown reference adapter.
5. Model source ACL principals and enforce permission-filtered search/fetch
   before making enterprise connector claims.

The full rationale, enterprise market references, boundaries, and exit criteria
remain in the [Adoption Roadmap](design/2026-07-16-adoption-roadmap.md).
